# Incident Reporting

`scripts/generate_incident_report.py` exports a correlated incident, its related alerts, its timeline, and an AI RCA as JSON/Markdown artifacts.

## Usage

```bash
python scripts/generate_incident_report.py --incident latest
python scripts/generate_incident_report.py --incident INC-6AC0889072
python scripts/generate_incident_report.py --offline           # no live API needed
python scripts/generate_incident_report.py --api-url http://localhost:8000
```

## Modes

- **Online (default):** calls the ingestion API (`/incidents`, `/alerts`, `/ai/rca/{id}`). If the API isn't reachable, or no incidents exist yet, it automatically falls back to offline mode.
- **Offline (`--offline`):** runs the detection engine, correlation engine, and AI agent directly against a freshly generated `full_attack_chain` scenario - no Docker, OpenSearch, or network access required. This is what `scripts/verify_demo.py` and CI use to confirm report generation works.

## Outputs

Written to `outputs/`:

| File | Contents |
|---|---|
| `sample_alerts.json` | The alert documents that made up the incident |
| `sample_incident_timeline.json` | The incident's chronological timeline |
| `sample_incident_report.md` | Full incident write-up: description, attack chain, affected assets, MITRE techniques, related alerts table, timeline, recommended actions checklist |
| `sample_ai_rca_report.md` | The AI root cause analysis (LLM or template mode), ready to paste into a ticket |

## Picking an incident

- `--incident latest` (default) sorts incidents by timestamp descending and picks the first.
- `--incident <id>` looks up a specific `incident_id` from the last 24 hours of incidents.

## Regenerating the RCA

The report generator calls `POST /ai/rca/{incident_id}` (not force-regenerated by default, so repeated report runs reuse the cached RCA). To force a fresh RCA, call the API directly: `POST /ai/rca/{incident_id}?force=true`.
